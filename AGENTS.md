# Repository Guidelines

## Project Structure & Module Organization

- `Assets/VRPlayer/Runtime/`: C# playback, storage, subtitles, rendering, persistence, and world-space UI under the `VRPlayer` namespace.
- `Assets/VRPlayer/Editor/`: project configuration and APK build commands. Keep Runtime, Editor, and Tests assemblies separate.
- `Assets/VRPlayer/Scenes/Player.unity`: production scene and the only scene in build settings. XRI Toolkit sample scenes/assets are intentionally not copied into this project.
- `Assets/VRPlayer/Shaders/` and `Assets/VRPlayer/Resources/Fonts/`: projection/subtitle shaders and Chinese fonts. Commit Unity assets with their `.meta` files; update existing font assets without changing their GUIDs.
- `Native/Android/`: Java Media3/SMBJ bridge; `Native/Rendering/`: C++ GLES texture plugin. Rebuild after native changes and commit changed runtime binaries in `Assets/Plugins/Android/` through the existing Git LFS rules.
- `Assets/VRPlayer/Tests/EditMode/`: NUnit tests. `Tools/` contains build/device scripts; `Docs/` contains plans, instructions, licenses, and validation records.

## Build, Test, and Development Commands

Use Unity **6000.3.23f1** with Android SDK, NDK, and OpenJDK support. Install Git LFS and run `git lfs pull` after cloning. Run commands from the repository root.

- `./Tools/Build-Native.ps1`: builds the Java AAR and ARM64 rendering library. Supply `-UnityEditor` for a different installation path.
- Unity menu **VRPlayer → Configure Project and Open Player**, then **Build Android APK**: configures the project and produces `Builds/LsVRPlayer.apk`. Use Play Mode for editor previews.
- Signed Release: `./Tools/Build-Release.ps1`; version comes from ProjectSettings, and secrets are passed only to external signing tools. See `Docs/Release.zh-CN.md` for the self-hosted GitHub workflow, signing setup, verification gates and tag publishing.
- Unity **Test Runner → EditMode → VRPlayer.Tests**: runs the NUnit suite.
- Native JUnit: run the Unity-bundled Gradle task `testDebugUnitTest` against `Native/Android`; the full PowerShell command is in `Docs/BuildAndUse.zh-CN.md`.
- `python Tools/Generate-TestMedia.py --extended`: generates fixtures; requires `imageio-ffmpeg`.
- `python Tools/Device-SmokeTest.py --serial <PICO_SERIAL>`: tests the running development APK with installed fixtures; requires Pillow. See `Docs/BuildAndUse.zh-CN.md` for fixture transfer and SMB setup.
- `python Tools/Device-ExperienceTest.py --serial <PICO_SERIAL> --host <TEST_PC_IP>`: checks quality, tabs, LAN discovery, shared folders, and cancellation. Use `Tools/Serve-LanTestSmb.py` for a fixture server; LAN testing requires Impacket and zeroconf.
- `python Tools/Device-CaptionTest.py --serial <PICO_SERIAL>`: captures subtitle distance and style cases for visual review. `Tools/Device-StabilityTest.py --serial <PICO_SERIAL> --cycles 18` exercises high-resolution fixtures and repeated playback changes. Keep the headset awake during device tests.
- `python Tools/Device-QuickControlsTest.py --serial <PICO_SERIAL>`: checks quick panels and hidden-panel stick distance controls on a development APK, using generated Recognition clips/SRT from `Tools/Generate-RecognitionMedia.py --clips`. Optional `--section panels`, `--section distance`, or default `--section all` runs the corresponding checks. See `Docs/QuickControls.zh-CN.md` for fixture prerequisites and verification boundaries.
- `python Tools/Device-BackNavigationTest.py --serial <PICO_SERIAL>`: checks global Y/B return, actual directory/source history, restored list positions and main/quick subtitle entry boundaries on a development APK. Requires the generated Recognition clips/SRT above; creates and removes run-owned directory fixtures and restores settings and command files. See `Docs/QuickControls.zh-CN.md` for coverage and input limitations.
- `python Tools/Device-SmbPlaybackTest.py --serial <PICO_SERIAL> --cases <IGNORED_CASES_JSON> --mode read-ahead --seconds 600`: tests SMB prefetch; use `--mode diagnostics` to disable prefetch for comparison. `baseline` mode requires the preserved original APK. See `Docs/SmbPlaybackDiagnostics.zh-CN.md` for case format and metrics.
- `python Tools/Device-EmbyTest.py --serial <PICO_SERIAL> --server <EMBY_SERVER_URL> --username <TEST_USERNAME>`: checks Emby browsing, original playback, progress and per-film settings; password comes from hidden input or temporary `EMBY_TEST_PASSWORD`.
- `python Tools/Device-EmbyMoviePartsTest.py --serial <PICO_SERIAL> --server <EMBY_SERVER_URL> --username <TEST_USERNAME> --require-parts`: checks complete walls, people/categories, same-film parts and extras; `--require-parts` fails if the designated known real multipart sample is absent.
- `python Tools/Serve-EmbyMoviePartsFixture.py --media <LOCAL_TEST_MP4> --duration-ms <ACTUAL_DURATION_MS>`: serves the loopback 205-item fixture. Use `--synthetic-fixture` for its device regression; `adb reverse` setup, ownership and cleanup are documented in `Docs/Emby.zh-CN.md`.

## Coding Style & Naming Conventions

Use four-space indentation, C# PascalCase types/methods, and camelCase fields/locals; use camelCase Java methods. Follow nearby brace placement and avoid unrelated reformatting; no formatter is enforced. Guard Android-only C# with `UNITY_ANDROID && !UNITY_EDITOR`. Keep file/network work asynchronous and GLES calls on the render thread.

Preserve the complete v1 → v2 → v3 settings migration, per-film subtitle Auto/Manual/Off states, saved projections, history/favorites, and stable `smb://configurationId/path` identifiers. Keep SMB discovery separate from credentials, cancel obsolete operations, and discard stale callbacks. Keep page selection and file-source state centralized, reuse visible directory rows, and isolate subtitle materials from menu text. Apply eye-buffer resolution only on initialization, XR recovery, or quality changes, not every frame.

Route format changes through `PlayerApp` so UI and diagnostics share manual-lock and undo behavior. Local/SMB explicit previous/next playback in the same folder inherits format fields; ordinary opens and automatic sequential playback retain per-film behavior. Emby same-film CD transitions are the inheritance exception described below. Preserve projection enum values, distinguish unknown fields from explicit Mono, and never equate SBS with VR180. Subtitle loading, metadata probing and frame analysis need independent cancellation and playback-generation checks. Frame sampling must not seek or block playback; validate persistent recognition caches against file metadata and algorithm/profile versions.

Keep full and quick panel visibility centralized in `PlayerUI`, use its active Canvas for input, consume the trigger press that opens the quick panel, and preserve visibility across adjacent playback. Cancel pointer operations on surface, focus, or tracking changes without committing cancelled seeks; another pointer must not take over an owned drag. Reuse stick axis arbitration for horizontal seeking, visible-list scrolling, and hidden-panel distance adjustment, requiring neutral after interruption. Route distance/zoom changes through `PlayerApp`; continuous stick adjustment saves on gesture end or existing periodic progress saves rather than every frame. Reset only the active distance type without changing formats or manual locks. Keep per-film distance and panorama zoom separate from adjacent format inheritance; panorama zoom uses the fixed video-forward direction shared by both eyes and must not follow head rotation or scale subtitles or UI. Require the same hand's grip before stick distance/scale adjustment; use vertical for distance (up moves farther/reduces panorama zoom, down moves nearer/increases panorama zoom), horizontal for flat-screen width or main-panel scale, and ignore gripped horizontal input for panoramas. Persist main-panel scale globally and flat-screen width per film, independently of distance and format locks. Keep the quick subtitle browser independent of the main file source and playlist, and preserve subtitle Off/restore information and version-3 defaults.

Keep SMB playback read-ahead bounded and on the Media3 loader thread. Capture playback sessions in data-source factories, cancel retired connections, and keep probing resources independent. Count actual network reads separately from bytes delivered from cache; aggregate diagnostics off playback threads without media paths or credentials. Preserve finite SMB request deadlines while allowing playback sockets to remain idle with full media buffers. Change load-control thresholds only with separate measurements.

Register existing Emby server accounts; keep account metadata separate from remembered tokens, bound to configuration ID, normalized server URL, server ID and user ID. Never persist passwords or place tokens in URLs, history or diagnostics. Preserve `emby://configurationId/itemId` identities across relogin and server-address edits. API, image and original-video authentication uses request headers; reject cross-origin authenticated redirects. Editor preview must not bypass this by adding tokens to video URLs. Keep original playback on the existing backend without silently enabling transcoding.

Use official `AdditionalParts`, `SpecialFeatures` and `LocalTrailers` results and server order; `ExtraType=AdditionalPart` is a CD part even with `Type=Video`, not an extra. Ordinary Emby movies cannot navigate or automatically advance to other films. Parts and extras queues stay isolated by account and main film. Same-film CD explicit selection, previous/next and automatic continuation inherit VR format fields and the inherited lock; extras inherit only on explicit previous/next, while direct selection restores their own settings and never auto-advances. Preserve each item's subtitles, distance, zoom and progress; single-item loop still takes precedence over continuation. Cancel stale browsing, authentication and playback work on account/source changes, stop or a replacement open, but keep committed queues and pending CD continuation through browsing within the same Emby source. Aggregate the complete library/person/category wall with bounded visible card pools and viewport-driven image requests/cache; discard stale generations, cancel offscreen requests and release textures.

Route left Y/right B and keyboard Esc through the shared global back path. Back follows actual visited pages and source roots, while the Up button visits the physical parent; never use URI parents as a fallback for Back. Capture each visit's query, sort, video/subtitle mode and scroll offset, including repeated visits to the same URI, and retain pending restoration through asynchronous loading and tab redraws. Explicit source changes clear main browsing history; top-level tab changes preserve it. Keep main and quick subtitle entry boundaries independent of older file history, and bound in-memory history/view/parent caches to 64 entries. Sample both hands before navigating so simultaneous or held presses return once; require release after focus, pause or tracking interruption. Do not commit cancelled drags or let stale directory/authentication callbacks overwrite a restored view.

Movie-level Emby resume follows the most recently played official part using server `LastPlayedDate`, account-scoped local history and a valid current snapshot. Keep current-part resume a separate action; do not infer recency from CD index or position magnitude. Resume restores that part's settings; same-group adjacent controls retain their inheritance behavior.

Persist Emby library view choices by stable account configuration ID and library root ID, defaulting to Poster; retain the root through searches and nested pages. Keep all seven views virtualized with view-specific geometry and independent scroll memory. Preserve artwork aspect ratios and Disc/Logo PNG alpha, hide loading placeholders after images arrive, and restore them when rows recycle. View menus consume Back before page navigation, block background scrolling, and reject stale selection callbacks after account/page changes.

## Testing Guidelines

Name tests after observable behavior, such as `PositiveDelayMeansLaterDisplay`; use `[TestCase]` for filename variants. Add regressions for changed parsing, timing, persistence/migration, seeking, or cancellation behavior. No percentage coverage gate exists. Wait for Unity compilation and check Console before editor automation.

Validate native/rendering changes on PICO hardware. Keep raw records in ignored `Docs/Validation/` and screenshots in ignored `Docs/Captures/`; commit curated Markdown reports under `Docs/` and reviewed, nonprivate screenshots under `Docs/Images/`, with reproducible commands and remaining limitations. Distinguish short fixtures from long-film compatibility, real LAN discovery from `adb reverse` playback tests, and screenshot/automated checks from subjective headset acceptance.

Quick-controls and back-navigation device automation use development-only simulated pointers, sticks and Y/B through the shared UI/input paths; they do not validate physical button bindings, trigger handling, readability, or headset comfort. Keep valid headset presence, application focus and fresh diagnostics throughout these checks; restore them and restart interrupted runs instead of combining partial results. Record physical-controller and worn-headset acceptance separately. Back-navigation fixtures and command staging paths must have verified run ownership before deletion; restore original file bytes or original absence, and fail the run if cleanup/restoration fails.

Do not modify PICO `screen_off_timeout` in device scripts: firmware may store `-1`, which Android's shell rejects when restoring. Back up and verify restoration of any temporary player or USB stay-awake settings, even after failed tests. External pauses or stale diagnostics invalidate a continuous playback run; restarting short runs does not satisfy a long-duration acceptance check.

Emby device regressions use a dedicated existing account not already registered on the device. Back up `settings.json`, `emby-accounts.json`, private `emby_accounts.xml` and its Android `.bak`, including original absence. Drain progress and logout work, force-stop before restoring device files byte-for-byte, and strictly restore/verify every changed server UserData field even after failure. Remove temporary commands, owned fixture processes and only newly added reverse mappings; failed cleanup fails the run. Keep focus/presence and fresh uninterrupted diagnostics, separate real LAN from synthetic results, and preserve failed runs. Private backups, server/account/media identifiers and screenshots stay in ignored validation directories until sanitized and reviewed; see `Docs/Emby.zh-CN.md` and `Docs/EmbyValidation.zh-CN.md` for scope and recovery.

Use `Tools/Device-ImprovementsTest.py`, `Tools/Device-AdjacentPlaybackTest.py`, and `Tools/Device-RecognitionStressTest.py` for the added playback regressions; see the current recognition report for fixture prerequisites and commands. Read real samples only from user-designated locations, store extracted frames in ignored `TestMedia/`, and restore device settings after tests. Keep stereo and VR180 projection approval gates separate in `FormatRecognitionProfile.json`: generated fixtures and calibration samples do not establish independent real-video accuracy. Pure-frame VR180 automatic projection remains disabled pending its validation gate; report coverage, abstentions, and false positives separately.

## Commit & Pull Request Guidelines

Use concise imperative subjects, e.g. `Fix subtitle timing after seek`. Keep commits focused and preserve unrelated working-tree changes. Review staged paths and partial-file changes before committing. PRs should describe behavior, link relevant issues, list tests/device details, and include selected screenshots for UI/projection changes after checking for private content.

## Dependencies & Sensitive Data

Use free/open-source additions and update `Docs/ThirdPartyNotices.md` and required license texts. Keep native and Unity Gradle dependency versions aligned; SMBJ-RPC must exclude its transitive SMBJ version in both dependency declarations.

Never log or commit SMB/Emby credentials, access tokens, device settings backups, or signing keys. Keep generated APKs, native build intermediates, `Library/`, `TestMedia/`, `Tools/.runtime/`, and raw device reports ignored. Preserve required Unity assets, `.meta` files, runtime AAR/SO files, and font sources; do not broadly ignore `Assets/Plugins/` or all binary assets. Keep serialized font `.asset` files under the existing Unity YAML rules and binary fonts/plugins under Git LFS.
