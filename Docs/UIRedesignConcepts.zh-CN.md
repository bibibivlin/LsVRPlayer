## 现有界面观察

依据 `PlayerUI.cs`、`UiFactory.cs`、`QuickControlsUI.cs`、`QuickControlsGraphics.cs`、`EmbyBrowserUI.cs` 和仓库中已评审截图：

- 完整面板大量使用同一种矩形按钮，主导航、文件来源、目录操作和播放操作缺少明显层级。
- 来源、地址、搜索、排序等多行工具区挤占内容空间；可通过工具区合并、来源分组和次级操作菜单提高可读性。
- 快捷控制已有圆角和图形图标，适合扩展为统一的组件语言。
- Emby 已有七种视图和虚拟化图片池；新的外观应复用这些能力。本地/SMB 文件继续使用可读列表，不以海报或新增缩略图抽取为前提。
- 完整面板当前基准为 1440 × 1040、缩放 0.00145、呼出距离 2 米。这是 VR 空间界面，桌面截图里的像素大小不能直接当作头显阅读与点击标准。

## 学习来源与适用范围

通过 `skill-installer` 查询官方技能目录，并阅读以下设计技能与参考资料：

1. [Anthropic frontend-design / SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)：按产品用途选择有明确个性的配色、排版和布局；先形成设计语言，再评审并制作。采用其设计思考方法，不把网页实现方式引入 Unity。
2. [UI UX Pro Max / SKILL.md](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/.claude/skills/ui-ux-pro-max/SKILL.md)：参考语义颜色、导航一致性、状态反馈、对比度和渐进展示规则；阅读其 quick-reference 与 pro-rules，并运行本地设计系统及 spatial / navigation / focus 查询。
3. [Apple Spatial layout](https://developer.apple.com/design/human-interface-guidelines/spatial-layout/) 与 [Design for spatial user interfaces](https://developer.apple.com/videos/play/wwdc2023/10076/)：参考中央视野、稳定空间位置、少量深度和控件间距。PICO 继续使用现有手柄射线交互；不照搬 visionOS 注视、手势、系统字号或点数。

设计系统查询返回了适合娱乐产品的深色方向，但同时带有网页营销 Hero 和 CSS/字体建议；这些不适用于播放器任务流，已排除。Spatial 查询确认了浅色空间界面这一备选方向；其低透明度与动态模糊建议也不直接照搬。研究脚本及数据位于被 Git 忽略的 `Tools/.runtime/ui-design-research/`，保留上游 LICENSE，仅供研究；没有全局安装技能，也没有增加运行时依赖。

## 三套方向比较

| 方向 | 视觉语言 | 浏览布局 | 适合偏好 | 实现侧重点 |
| --- | --- | --- | --- | --- |
| A 深色影院（推荐起点） | 墨蓝、海盐青、克制圆角、低干扰 | 顶部主导航 + 页内来源侧栏 + Emby 海报 | 沉浸观影、兼顾美观与清晰 | 共用主题、圆角组件、焦点与播放层级 |
| B 雾面空间 | 雾灰、瓷灰、钴蓝、留白较多 | 左侧主导航 + 页内来源分段 + Emby 海报 | 清爽、轻盈、空间应用感 | 重排导航、浅色状态与亮暗视频背景验证 |
| C 专业控制台 | 矿物灰、琥珀、紧凑规则、标签更明确 | 顶部主导航 + 页内来源侧栏 + Emby 列表 | 文件管理、频繁调参、操作可发现性 | 列表层级、明确状态、统一快速调节组件 |

A、B 概念图展示 Emby 海报视图，C 展示 Emby 列表视图；这是展示选择，各方案都保留七种视图及已有视图记忆，不强制修改默认 Poster。

### A 深色影院

![A 深色影院](Images/UIConcepts/A-MidnightCinema.png)

颜色：背景 `#10161D`，面板 `#1A242E`，强调 `#62D5C7`，正文 `#F2F6F7`，次级文字 `#B0BAC6`。主要按钮上的文字使用深色，避免浅色字压在浅青底上。

较大的窗口圆角与较小的控件圆角形成层级。导航选中用下划线，来源选中用填充，播放用更明显的主按钮。海报是内容中心；工具栏保持安静。快捷条与完整面板共用颜色、图标和按钮反馈。

### B 雾面空间

![B 雾面空间](Images/UIConcepts/B-FogSpace-v2.png)

颜色：环境 `#D7DFE4`，面板 `#F0F4F5`，正文 `#1C2C3A`，次级文字 `#50616E`，强调 `#315CCA`，主按钮文字 `#FFFFFF`。

留白更大、外轮廓更柔和，主要导航移到左侧，媒体来源在内容内分段选择。使用近不透明的灰色表面与细微边缘表现空间感。图中雾面质感是视觉意向；不以实时模糊、玻璃折射或眼动追踪为前提。播放时快捷控制可采用同语言的深灰表面，减少大片浅色区域对影片的干扰。

### C 专业控制台

![C 专业控制台](Images/UIConcepts/C-PrecisionConsole.png)

颜色：背景 `#191918`，面板 `#262723`，行表面 `#30312D`，正文 `#F5F0E7`，次级文字 `#BEBCAF`，强调 `#E8B56A`。强调按钮采用深色文字。

用列表、对齐、明确标签和更小的圆角体现精确感。关键信息无需等悬停才出现；影片名称和进度具有明确主次。强调色用于选中项、播放按钮与调节轨道，避免把界面变成诊断仪表盘。

## 各方向共同的交互规范草案

静态、不透明色板的 sRGB 对比度计算结果如下。它只验证指定颜色组合，不代表生成图中所有像素或 PICO 实机验收通过。

| 方向 | 正文 / 面板 | 次级文字 / 面板 | 主按钮文字 / 强调底色 |
| --- | --- | --- | --- |
| A | 14.45:1 | 8.00:1 | 10.27:1 |
| B | 12.89:1 | 5.79:1 | 5.98:1 |
| C | 11.54:1 | 6.86:1 | 9.42:1 |

- 媒体浏览、观看时快捷控制、完整设置分层；概念板下方的小面板代表另外的界面状态，不是要求同时打开多个窗口。
- 保留文件、投影、字幕、设置、信息五个主页面，以及本地、SMB、Emby、收藏、最近五个来源的明确身份。返回与物理上级保留独立动作。
- 全局 Y/B/Esc 返回、历史与滚动恢复、字幕选择边界、弹层先返回的语义沿用现有实现。
- 控件状态至少含默认、射线悬停/焦点、按下、选中、禁用；用轮廓、填充、文字或勾选共同表达，不能只靠颜色。焦点反馈不改变实际布局或拖动命中范围。
- 设计基准采用 8 单位间距节奏；完整面板正文初始目标 28–32 Canvas 单位、主要操作高度 64–72、图标按钮可见尺寸 36–40、命中区域至少 64 × 64。它们是原型起点，需按实际世界尺寸、距离和视角重新校准。
- 正常文本对比度目标至少 4.5:1，重要非文本控件和焦点轮廓目标至少 3:1；透明合成、禁用状态与头显实际观感另行验证。次级字保持可读，不用极细字重。
- 继续复用现有中文字体与 GUID；用同一图标笔画体系，圆角、间距、颜色和文字层级共用设计 token。
- 投影与立体布局始终分成两个区。平面、VR180、VR360、鱼眼、Cubemap、EAC 和 2D/左右/上下保留现有能力；概念图为了可读性仅展示常用项，其他项放入高级区。
- 平面距离与全景缩放按当前投影显示，重置只影响当前距离类型；格式手动锁、撤销、相邻播放继承与每影片字幕/距离/缩放保持现有语义。
- 快捷字幕选择继续独立于主文件浏览；快捷条的停止操作明确命名为“停止并返回”。呼出按压消费、拖动所有权、取消手势和摇杆回中规则保持。
- UI 在呼出时对齐视线，之后维持稳定空间锚定；不新增持续追随头部的主面板。短暂淡入/状态过渡只解释操作结果，不加入持续漂浮与背景动画。
- 加载、空内容、读取失败和重试采用同一套反馈组件。静态占位在图片到达后隐藏，循环使用行时恢复；Emby Disc/Logo 保留透明通道。

## 选定方向后的施工顺序

1. 固定所选方向的颜色、文字、间距、图标与状态规范，并制作主浏览、投影、字幕、设置、详情和空/错误状态原型。
2. 共用组件改造，再接入完整面板与快捷面板，复用现有浏览及播放器行为。
3. Emby 七种视图、长标题、分段/花絮详情、来源连接表单及虚拟键盘采用统一外观。
4. Unity 编译与相关 EditMode 检查，随后执行快捷控制、返回导航、Emby 相关设备回归；真实手柄与佩戴头显的阅读、点击和舒适度验收单独记录。

当前未改动 `Assets/`、`Native/` 或项目设置，也未执行构建/设备测试。仓库原有 `ProjectSettings/ProjectSettings.asset` 未提交改动保持原样。
