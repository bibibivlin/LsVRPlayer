# VR180° SBS 专项识别优化方案

日期：2026-09-09。此文保留实施前的问题与目标；当前进展、实测结果和未达标项见 [0.6 阶段交付记录](VR180SbsRecognitionResults.zh-CN.md)。

用户已确认两点：这批影片的文件名没有体现投影格式，漏判后仍显示“平面／普通 2D”。本专项以无文件名格式提示的自动识别为主，文件名解析修复不能解决这批问题。无文件名提示不等于容器没有元数据，仍须独立检查。

最先排查自动流程是否启动、SBS 是否检出，以及是否被更强的 2D 证据阻止，随后补齐 180° 投影自动应用。首批目标是手动选择“等距柱状 180°＋左右 SBS”即可正确观看的视频。原生相机鱼眼、专用投影网格、裁剪与偏转必须另行分类，不能将它们统一套用到等距柱状 180°。用户实际漏判视频尚未进入本次复测，以下区分代码已确认的问题与需要样本验证的假设。

## 1. 已确认的漏判原因

| 环节 | 当前实现与复测 | 影响 |
| --- | --- | --- |
| 180° 自动应用 | `FrameFormatAnalyzer` 对近方形单眼仅给 `vr180=0.68`；`AcceptFrameEvidence` 只将立体排列写入 `frameHints`，投影始终为建议 | 无元数据／明确标签时，画面路线无法自动完成“180°＋SBS”组合，单独放宽 SBS 门槛无法解决 |
| 文件名（旁支问题） | 复测发现度数符号和紧凑组合标签存在解析缺口，但用户这批影片没有文件名投影提示 | 不作为本批漏判的解释；移至后续兼容性修复，不计入专项收益 |
| SBS 匹配 | 单眼强行缩为 128×96；5×5 小块，仅搜索整数水平位移 ±8；相关性 ≥0.94；零位移全部排除；至少 75% 匹配需同一视差符号 | 低视差、纵向错位、广角形变和跨零视差容易失败。算法偏向理想平移纹理 |
| 受控复测 | 512×256 合成 SBS：标准水平视差得分 1.000；0.3 原图像素视差、3 像素上下错位、上下区域正负视差混合均为 0.000 | 确认上述限制会触发漏判；这些是机制测试，不是对真实影片的准确率评估 |
| 时间聚合 | 首个全局亮度／方差有效帧即开始 10 秒窗口，最多 8 次采样；所有有效帧等权平均 | 有纹理的平面片头会消耗窗口并稀释后续立体证据；静态内容与低纹理区域处理不充分 |
| 缓存与完成状态 | 有 `frames` 缓存即视为画面工作完成；`frameApplied` 是单一标志 | 已确认 SBS 但未确认投影时，无法表达“继续只识别投影” |
| 验证范围 | 当前 56 个阳性样本由同一纹理水平平移生成，只评估 SBS/OU 标签 | 不能证明真实 VR180 投影识别能力；必须重新验证完整格式组合 |
| 已保存设置 | 旧历史、手动选择、上一部／下一部继承均使用 `formatLocked` | 属于跳过自动识别，不应统计为模型漏判；应明确显示原因，保留用户已要求的继承行为 |

现有 `Half/Full` 只参与平面屏幕比例计算，180° 球面着色器不使用它。将 Half 改成 Full 不会修复当前 VR180 自动切换问题。

## 2. 第一阶段：修复确定性缺口

### 2.0 先定位为什么仍是普通 2D

为当前影片记录不含私人文件名的诊断摘要：锁定原因、识别开关、是否启动采样、GPU 回读状态、有效帧数、SBS/OU 评分、匹配区域覆盖率、拒判条件、元数据是否显式声明 Mono、最终采用证据。投影页用简短中文显示主要原因。

用户主动“重新识别格式”后仍为 2D 时，按实际原因走对应修复：未启动／未取得画面修生命周期；有画面但 SBS 低分修匹配；SBS 有足够证据却仍 Mono 修合并／应用；SBS 已成功后再处理 180°。不得把所有失败归因于样片不规范或只让用户改名。

### 2.1 元数据与纯画面两条路径

无文件名格式提示时，分别处理：

- 存在明确、受支持容器元数据：直接确认对应字段，画面仅补充缺失字段。
- 元数据缺失或信息不全：启动正常解码纹理上的 SBS 与投影分析；未知不等于 Mono，不以元数据缺失为理由保留强 2D 结论。
- 存在显式冲突或不支持的网格：显示原因，不能以宽高比覆盖可靠字段或伪装为支持的投影。

增加字段来源与“确实存在”状态，核对 Media3／容器中的未声明字段与显式 Mono。整个流程不要求重命名影片、手工补标签或先设置目录偏好。

### 2.2 拆分完成状态与应用门槛

立体排列和投影分别记录 `Unknown / Candidate / Confirmed / Unsupported`、来源、支持帧数与完成状态，替换单一 `frameApplied`。例如：

1. 元数据已经确定 180°，只补 SBS；元数据也缺失时，两项均由画面流程提出候选。
2. 画面已经确定 SBS，继续识别投影。
3. 两项都确定后停止；只有一项确定时，不因缓存提前退出。

识别配置增加独立的 `sbs` 与 `equirect180Sbs` 验证许可。原有 `stereoAutoApproved` 不得授权 180° 自动应用。算法版本升到 2，旧自动识别缓存失效；手动格式和切片继承设置保持。

UI 区分“已识别 SBS，正在判断投影”“继承格式，未运行自动识别”“画面不足”“存在冲突”“不支持的网格”。所有自动判断仍可撤销；重新识别只解除当前片的固定格式。

## 3. 第二阶段：针对真实 VR180 改造 SBS 检测

保持本地处理、异步 GPU 回读及单个后台分析任务，不额外解码或跳转视频。

### 3.1 有效区域与多尺度匹配

- 左右眼保持单眼原比例，建立图像金字塔；优先分析中央区域，同时取多个侧边区域验证覆盖度。
- 先估计稳定黑边、镜头遮罩和叠加字幕区域，降低其权重。保留原图尺寸与裁剪变换用于投影判断，不能把裁掉黑边后的比例直接当作源投影比例。
- 使用局部归一化亮度、梯度／Census 特征组合，容忍左右眼曝光和压缩差异。
- 粗层搜索较宽的横向范围，细层做小范围二维修正与亚像素插值。初始探索范围为单眼宽度的约 ±12%、细层纵向 ±3 像素；均需真实验证集校准，不作为已经验证的硬常数。
- 用双向匹配、最佳／次佳差距、局部几何一致性剔除错误对应。匹配覆盖至少多个独立区域，避免一个 logo 就决定整片格式。

### 3.2 去除导致高漏判的绝对条件

- 零／近零视差计入左右眼同源证据，但单靠相同图像不判立体；仍需部分可靠深度差异，或独立标签／投影证据。
- 移除全局 75% 同号视差条件，检查局部连续性、双向一致性和多区域深度分布。正负视差混合本身不作为拒判理由。
- 不简单把相关性从 0.94 改成某个更低值；用组合证据与反例校准最终门槛。
- 完全复制画面、镜像、普通分屏、同一平面图片的全局平移必须保留为反例。无法与重复画面区分的远景或纯平面场景保持不确定。

## 4. 第三阶段：补齐 180° 投影判断

### 4.1 一般模式：多种投影候选竞争

确认 SBS 之后，同时比较平面 3D、等距柱状 180°、等距柱状 360°与双鱼眼。画幅只用于提出候选：例如总图 2:1、单眼接近 1:1 支持 VR180 候选，但不能独立触发 VR。

在后台利用稀疏左右眼匹配点，对候选投影分别转换为单位视线方向，比较跨区域的双眼几何一致性。先以中央区建立对应关系，再检查侧边／上部区域是否更符合球面投影；场景覆盖不足或多个候选接近时弃判。

辅助证据包括边缘拉伸与纬度相关变形、跨帧稳定的圆形镜头边界、360° 首尾接缝。它们需要真实纹理和空间覆盖；普通网格线、缺少接缝或一帧黑边不能独立证明 180°。鱼眼边界不完整时避免强行确认等距柱状。

此部分是待实现和验证的模型选择策略，不能预先保证任意自然画面都可区分。只在 `equirect180Sbs` 独立验证通过后开放对应自动应用。

### 4.2 面向大量同类影片的可选目录偏好

增加用户明确设置的“此目录优先 VR180 SBS”。对直接从该目录首次打开且没有逐片固定格式的文件：

- 先检查明确的 2D／360／鱼眼／不兼容网格证据；有冲突则保留证据更强的结果或提供建议。
- 没有冲突且画面确认 SBS 时，可按目录偏好补齐 180°，显示来源“目录偏好＋左右分眼”。
- 完全无法辨认左右眼时不强制套用。不能仅因目录里过去有一部 VR180，就静默给其他影片套用该格式。
- 独立统计“纯自动识别”与“目录偏好辅助”成功率，不能用后者抬高算法准确率。

优先级为：当前逐片手动／上一部下一部继承 > 明确受支持元数据 > 明确文件名 > 用户目录偏好 > 已验证画面推断 > 几何弱线索。目录偏好按稳定目录 URI 保存，不更改 SMB 配置 ID。

这是在自然画面本身存在歧义时提高同类片库使用成功率的补充。默认通用模式仍须依靠证据确认投影。

### 4.3 原生 VR180 相机文件

Google VR180 相机规范采用双眼网格，允许鱼眼画面、裁剪和缩放；其“VR180”标签不保证等距柱状映射。先明确区分“已识别为 VR180 相机格式”与“现有渲染器可正确播放”。不能通过解除网格限制来虚增成功率。[VR180 规范](https://github.com/google/spatial-media/blob/master/docs/vr180.md)

本轮优先覆盖可由现有 180° 渲染器正确显示的文件。旧球面裁剪元数据可补充识别严格等价的居中半球映射；非标准裁剪、方向变换必须匹配实际渲染能力，复杂网格作为单独的渲染扩展任务。

## 5. 采样、缓存与性能

- 初始 20 秒有效播放窗口最多 12 次采样，每秒不超过 1 次；若片头或不确定画面占主导，可延伸到 60 秒，总上限 20 次。
- 正常内容获得至少 3 个有空间覆盖、跨时间一致的支持帧即可提前结束。低信息帧不当作反证；有明确相反布局的正常内容仍必须扣分。
- 对场景切换分段聚合，以当前稳定内容段判断，避免片头长期稀释后续结果。每段仍需足够支持，不能任意挑最高分的三帧。
- 首阶段使用最长边 512；确实存在歧义时，最多 4 次升级为最长边 768。先测粗分析成本再确定是否开启此分支。
- 复用回读纹理和缓冲区，后台做灰度转换、匹配和投影评分；主线程只负责提交、轻量结果检查和格式应用。
- 用户暂停、切片、失焦、手动修改或继承格式时按原机制取消／丢弃过期结果；不会自动拖动播放进度取样。
- 缓存增加逐字段完成状态、算法／配置版本、使用的目录偏好版本。信息不足的 URI 仍只在本次播放复用；不保存完整视频帧，不写日志中的私人文件名。
- 手动锁定／继承来源增加独立标识，以便说明为什么未运行；旧 `formatLocked` 保守迁移为“已保存”，不批量解除。

性能验收仍为识别主线程 p95 ≤1 ms、平均帧率下降 ≤5%。上一轮 p95 最高 2.122 ms 尚未达标，本次须一并优化和复测；不能通过只统计空闲帧或只报平均值来满足目标。

## 6. 验证集与成功率定义

先用少量有代表性的真实漏判影片建立诊断基线，再扩充按原始影片／拍摄来源分组的校准集和独立验证集。同一影片的不同片段不能跨两组。只在用户指定的样本范围内读取画面，本地分析。

主验收使用无格式提示的文件名，关闭目录偏好，清除本次测试的自动识别缓存，并使用没有逐片手动／继承固定格式的测试记录。元数据存在与缺失分别统计；另在测试副本上移除格式元数据或在离线验证入口禁用元数据输入，以独立测量纯画面效果，不修改用户原文件。不允许以改名后的识别、目录默认值或先前保存的格式算作本专项自动识别成功。

阳性至少覆盖：4K／6K／8K、H.264／HEVC、近零与大视差、正负视差、微小纵向错位、前景近物、曝光差异、模糊压缩、黑边、水印、平面片头、实际 180° 裁剪及不同比例。阴性包括普通平面 SBS、Half/Full 3D 电影、2:1 单目普通视频、360°、双鱼眼、镜像、复制画面、分屏和动画。

生成样片须改为双相机渲染有真实深度层次的三维场景，并分别输出平面、等距柱状 180/360 与鱼眼投影；两张纹理简单平移和普通画网格只做单元测试。

拟定验收目标（不是当前成果）：

| 指标 | 目标与口径 |
| --- | --- |
| 主目标：纯画面 VR180 SBS | 无文件名提示、无可用格式元数据、无目录偏好／缓存／固定设置；完整“等距柱状 180°＋SBS”自动应用正确率 ≥98%，真实阳性覆盖率目标 ≥90% |
| 无文件名提示、有元数据 | 单独报告受支持元数据的字段应用率与完整组合覆盖率，不与纯画面结果合并 |
| 用户明确目录偏好 | 单独报告覆盖率，目标 ≥95%，仍统计误套用和弃判 |
| 验证规模 | 独立真实验证集至少 200 部阳性、200 部反例，公布每类样本数与置信区间；未收集齐时只能报告阶段结果 |
| 识别时延 | 有效内容开始后，中位数目标 ≤5 秒、p95 ≤20 秒；片头等待单独记录 |
| 误判与限制 | 平面 3D、鱼眼和复杂网格误套 180°均算错误，不能只统计 SBS 判断正确 |
| 功能回归 | 手动锁定、前后切片继承、重识别与撤销、缓存失效、慢 SMB 与过期回调、字幕和暂停状态 |

分别报告：SBS 检出率、180° 判定率、完整组合正确率、阳性覆盖率、弃判率、误切换率、跳过识别的原因和时延。对一般模式始终达不到投影正确率要求的类别，只保留建议或显式目录偏好；不凭合成集成绩直接开放。

## 7. 实施顺序与代码落点

1. `PlayerFormatDetection.cs`、`VideoFrameSampler.cs`：诊断无标签影片为什么停在普通 2D；复核元数据字段是否存在、采样是否运行、强证据是否阻止画面结论。
2. `FormatDetection.cs` 与上述流程：拆分排列／投影完成状态、证据来源、算法与缓存版本，避免只确认 SBS 就停止；调整采样窗口与分段聚合，保留切片继承优先级。
3. `FrameFormatAnalyzer.cs`：等比采样、多尺度二维与亚像素匹配、稳健聚合，先提高真实 SBS 覆盖率。
4. 新增 VR180 候选投影评分模块：稀疏匹配点的投影几何比较；按纯画面完整类别验证后打开 180° 自动应用。
5. `PlayerUI.cs`、`PlayerStore.cs`：清晰的识别阶段／原因；已有手动选择和历史完整保留。目录偏好作为可选补充，不是主流程依赖。
6. 验证工具与 PICO：真实无标签样本基线、纯画面与元数据分组结果、独立留出集、物理投影生成样片、性能记录、最终 AAR（仅原生变更时）与 APK。

本轮主线为“确认无标签识别运行 → 提高真实 SBS 检出 → 区分并应用 180° → 无外部提示验收”。不能把所有 2:1 SBS 当作 VR180。度数符号、中文描述、紧凑组合标签的解析改进另列后续兼容性修复，不作为本轮交付前置条件或收益指标。

参考：字段独立语义见 [Media3 Format](https://developer.android.com/reference/androidx/media3/common/Format)；球面裁剪与映射见 [Spherical Video v2](https://github.com/google/spatial-media/blob/master/docs/spherical-video-v2-rfc.md)。上述参数与目标均需用真实样片校准。
