本文保留 0.5 的交付数据；当前 0.6 识别优化、安装包及验收状态见 [VR180 专项记录](VR180SbsRecognitionResults.zh-CN.md)。

日期：2026-09-09。Unity 6000.3.23f1；PICO 4；Android ARM64 / IL2CPP / GLES3 / Media3。两批内容均已合入当前工作区：第一批为自动字幕、历史目录、摇杆和元数据识别；第二批为少量帧分析、验证门槛和识别说明。用户原有 ProjectSettings 的预加载资源移除保持不变。

## 交付行为

| 项目 | 行为 |
| --- | --- |
| 自动字幕 | 默认关闭。开启后按中文后缀、无后缀、其他白名单标签加载同目录同片名 SRT；损坏候选继续尝试。自动／手动／关闭逐片持久化；支持恢复自动选择。 |
| 历史目录 | 每条“最近播放”增加“所在目录”，打开文件页、清空搜索、恢复视频过滤并滚动定位目标；当前播放代次不变。旧本地／SMB 记录可推导父目录；SAF 只使用保存的授权目录。 |
| 上一部／下一部 | 点击按钮切换同目录视频时继承切换前的投影类型、立体排列、Half/Full、眼序和鱼眼角度，覆盖目标影片原格式并持久化为固定格式。自动识别不会覆盖，可主动重新识别。目标影片的观看距离、亮度、单眼 2D、字幕和续播进度保留。播放列表绑定播放目录，浏览其他来源不改变切片范围。 |
| 摇杆 | 左右手都支持每次 ±10 秒；阈值 0.65，回中 0.25，横向至少为纵向的 1.35 倍。保持 0.5 秒后每 0.3 秒重复；手势轴向和首个手柄锁定，反向需回中。文字输入、弹窗、拖动、失焦和断连抑制触发。暂停跳转保持暂停，待执行目标累加并限制到有效时长。 |
| 格式识别 | 默认增强识别，也可只用元数据与标签或关闭。投影、立体排列、Half/Full、眼序分别判定；用户手动设置优先，其次为受支持元数据、明确标签、多帧分析、几何弱线索。同级冲突保留候选并提示。 |
| 手动控制 | 投影页显示来源和建议；“重新识别格式”解除手动锁定，“撤销本次识别”恢复原格式并锁定，“采用建议”作为手动选择。自动结果只更改格式字段，保留距离、大小、亮度、字幕等观看设置。 |

设置迁移按 v1→v2→v3 顺序运行。旧字幕非空为手动选择，空字幕为自动状态；旧投影全部视为保存设置，升级不会改变观看效果。保持原有投影枚举及 `smb://配置ID/路径` 标识。直接从文件页／历史打开影片，以及播放结束后的自动目录连播，仍使用目标影片自己的保存设置或自动识别；格式继承针对手动点击上一部／下一部。

字幕发现与读取、原生元数据探测、GPU 回读与后台图像分析有各自的取消状态，并校验播放代次或任务修订号。手动选择、关闭、停止及切片不会接受旧字幕结果。缓存要求 URI、非零大小、修改时间与算法版本全部匹配，文件信息必须来自实际目录读取；历史记录中的旧大小和时间不能验证缓存，信息不足时重新分析。

## 格式支持范围

原生探测器使用独立本地／SAF／SMB 句柄；按容器结构跳过媒体负载，读取预算 2 MiB，期限 3 秒。MP4 支持 `st3d`、`sv3d/proj`、兼容 `equi/cbmp` 和旧 GSpherical 标签；MKV/WebM 支持立体布局和投影字段。Media3 `stereoMode` 与 `projectionData` 分别提供布局和投影证据。未知、截断、超限、不可定位及不兼容字段保留未知，播放继续。

明确文件名支持 `SBS/LR/HSBS/FSBS/OU/TB/HOU/HTB/FOU/FTB/180/VR180/360/VR360/Fisheye/EAC/Cubemap` 等词边界标签。单独的 `3D/VR/4K/8K` 不决定格式。仅有 SBS/OU 标签不会自动选择 VR；只有分辨率／比例也不会自动选择 VR。

增强模式在尚未投影的解码纹理上异步采样，最长边 512 像素，间隔至少 1 秒。首个有效画面后累计正常播放 10 秒内最多 8 帧；暂停和失焦不消耗窗口。黑场片头最多等待 30 秒正常播放时间。灰度转换、重复画面检查、局部纹理相关与水平视差在后台运行，最多一个分析任务；不支持 GPU 回读时退回标签和元数据。

SBS/OU 自动应用要求评分 ≥0.90、领先次选 ≥0.15、至少 3 个有效帧一致支持，每次播放最多应用一次。分屏、镜像、黑场、低纹理和重复帧均有拒判规则。规则评分不代表准确率。180/360 的比例／接缝和鱼眼圆形边界评分仅显示建议；尚未验证的投影类型不开放画面自动切换。

不支持相机专用 VR180 网格、任意裁剪／方向变换、任意 Cubemap 面顺序、MVC 或 MV-HEVC 新解码路径。Cubemap/EAC 仅适配现有 3×2 渲染布局。元数据声明网格时不能将它当作等距柱状 180°。

规范依据：[Media3 Format](https://developer.android.com/reference/androidx/media3/common/Format)、[球面视频 v2](https://github.com/google/spatial-media/blob/master/docs/spherical-video-v2-rfc.md)、[VR180](https://github.com/google/spatial-media/blob/master/docs/vr180.md)、[Unity AsyncGPUReadback](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Rendering.AsyncGPUReadback.html)。没有新增收费依赖或云端分析。

## 独立画面验证

`Tools/Generate-RecognitionMedia.py` 生成有纹理表面和水平视差的独立验证集；与 NUnit 的逐像素随机纹理测试分开。共 84 组三帧图像，包含 56 组 SBS/OU 阳性和 28 组普通画面、分屏、镜像、黑场反例。现有红蓝分眼样片只验证渲染，没有作为识别证据。

| 指标 | 本次独立生成样片结果 |
| --- | --- |
| 自动应用正确率 | 56 / 56 = 100% |
| 阳性覆盖率 | 56 / 56 = 100% |
| 错误自动应用 | 0 |
| 弃判率（含阴性） | 28 / 84 = 33.33% |

达到至少 50 个自动应用样本、正确率 ≥98%、阳性覆盖率 ≥80% 的配置门槛，因此算法版本 1 的 SBS/OU 画面自动应用已启用。指标只统计立体排列，不代表投影或 Half/Full 的正确率，也不是对真实影片分布达到 98% 准确率的声明。真实影片、低视差和压缩严重内容仍需扩充验证；不能确定时保持平面 2D 或提供建议。

生成的移动视频另外通过 PICO 正常解码纹理验证：无标签 SBS、OU、黑场后 SBS 均可自动识别；普通 2:1、分屏、镜像未误切换。180/360/鱼眼网格片用于标签和投影通路检查。

## 尚待验收

- 实体左右手柄的手感、斜拨容错、两手竞争及弹窗输入的佩戴体验：状态机自动测试通过，未以真实手柄动作完成全部场景。
- SAF 实际系统授权／撤销、已删除 SMB 配置、中文与转义路径的全套设备组合：父目录和路径规则有自动测试，尚未穷尽真机授权场景。
- 不同真实影片来源的识别准确率、长片慢 SMB 取消、持续 8K 高码率无线吞吐和热稳定性。
- 识别主线程执行片段 p95 ≤1 ms：当前实测最高一轮 2.122 ms，仍未达标；平均帧率下降 ≤5% 已通过本次短片对照。
- 无标签 180/360/鱼眼的可靠自动应用、极区变形特征校准、任意 Cubemap/EAC 布局及复杂相机网格；当前相关画面结果只作为建议或标记不支持。
