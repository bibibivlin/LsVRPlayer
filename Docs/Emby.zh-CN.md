# Emby 媒体服务器

在完整主面板的“文件”页选择与“本地、SMB、收藏、最近”同级的 **Emby**。首次进入点击“添加服务器 / 账户”。点击协议按钮切换 **HTTP / HTTPS**，分别填写 **IP 地址或域名**与**端口**，再填写用户名和密码。新增配置默认 HTTP、端口 **8096**；切换协议不会改变输入的地址和端口。地址无需输入 `http://`、`https://` 或端口，可在域名后附加反向代理路径。已有配置重新登录时会回填原协议、地址与端口；地址不要包含用户名、密码或令牌。

当前构建与真机检查结果见 [Emby 接入验证](EmbyValidation.zh-CN.md)。

这里的“添加 / 注册”指将已有的 Emby 服务器和账户登记到播放器，不会创建服务器或服务器用户。可添加多个服务器，也可为同一服务器添加多个账户。在“账户与服务器”中切换、重新登录或移除配置。“记住登录”允许下次启动恢复该账户；密码不保存，登录令牌通过设备凭据存储保存。关闭后仅本次运行可用，重启后需重新登录。

## 浏览与播放

Emby 页面使用深色背景和绿色重点色。首页提供“我的媒体”“继续播放”“最新加入”；进入媒体库后，全部影片显示在同一个连续滚动的海报墙中，并显示年份及已看状态。上方搜索当前媒体库，摇杆上下滚动，无需翻页；从影片详情返回时恢复原来的列表位置。剧集、季、合集与播放列表可继续进入。影片详情显示海报、简介、类型、标签、制片厂、年份、时长、评分及演员 / 主创资料；资料是否完整取决于服务器。

点击演员 / 主创图片进入人物详情，查看头像、姓名、简介，以及服务器提供的出生日期、出生地等资料。下方连续海报墙显示该账户可访问的全部出演电影，可继续进入影片详情，再返回人物页或原影片。点击影片的类型、标签或制片厂，会显示该账户所有可访问电影中符合条件的影片，范围跨媒体库；上方搜索会在当前分类结果内筛选。

电影库使用 Emby 的影片元数据列表，影片文件夹不会作为海报墙的额外一级；点击海报直接进入正片详情。普通电影的“上一部 / 下一部”不会切换到另一部电影。未开启单片循环时，即使开启“连播”，播放结束也会停止；开启单片循环则重复当前影片。其他电影需从海报墙等入口选择，并恢复各片自己的设置。

服务器识别的分 CD 正片显示在简介之后、演员表之前的“额外部分”，包含主片与服务器返回的后续部分，顺序沿用服务器。点击分段卡片，或播放后使用“上一部 / 下一部”，只在同一正片的分段组内切换；浏览其他页面不会替换正在播放的分段队列。未开启单片循环时，在设置中开启“连播”后，会自动进入下一部分，最后一部分结束时停止；开启单片循环则重复当前部分，不自动接段。这些同片分段的显式切换和自动接段会继承当前 VR 格式及手动锁定；各段自己的字幕、距离、缩放和播放进度仍独立保存。

PV、CM、花絮和本地预告片从 Emby 官方附加内容接口读取，显示在演员 / 主创之后的“附加篇”。直接点击附加篇会恢复该项自己的 VR 设置并独立播放；播放中使用“上一部 / 下一部”，只在同一正片的附加篇组内切换，并继承当前 VR 格式及手动锁定。到达组内边界时停止切换，不会进入正片或另一部电影；附加篇播放结束不会自动接下一项，即使开启“连播”也一样。每项自己的字幕、距离、缩放和播放进度仍独立保存。海报和缩略图随滚动按需加载，图片缓存保持有界。

“额外部分”与“附加篇”采用服务器的分类，不按名称中的 CD、PV 或 CM 猜测。服务器需按 [分段正片命名](https://emby.media/support/articles/Movie-Naming.html#split-video-files-file-stacking) 和 [附加内容命名](https://emby.media/support/articles/Movie-Naming.html#movie-extras) 识别对应文件；未识别的文件需先在服务器端调整和重新扫描。

详情页“播放”从头播放；已有进度时显示“继续播放”和“从头播放”。播放器使用服务器的原始视频，通过当前 Media3 和现有渲染路径播放。设备需要支持原始容器、视频和音频编码；本功能不会自动转码为平面视频。原有 Flat、VR180、VR360、鱼眼、Cubemap / EAC 与 Mono、SBS、OU 格式控制继续可用，手动格式通过原有 PlayerApp 路径锁定和保存。

播放进度与 Emby 同步，暂停、换片和停止也会提交进度。逐片格式、字幕状态、观看距离和全景缩放沿用播放器现有保存行为；影片以稳定的 `emby://账户配置标识/影片标识` 保存到“最近”。媒体历史不保存服务器播放令牌。返回本地或切换账户会取消旧的媒体库读取，防止稍后返回的结果覆盖当前页面。海报读取也会随页面切换取消，并限制并发、响应大小及缓存。

现阶段不提供服务器用户管理、Emby 管理员功能、服务端转码策略或离线下载。自签名 HTTPS 证书需要设备正常信任。HTTP 服务器需与头显处于可访问的网络；网络隔离或设备不支持的原始编码会影响浏览 / 播放。

Unity 编辑器可登录并预览 Emby 页面；Emby 视频播放需要 Android 头显。编辑器的 VideoPlayer 不支持认证请求头，因此不会将登录令牌放入视频 URL。

## 真机复现

安装当前 Android Development APK 后，连接 PICO 并保持播放器前台、佩戴感应有效。测试账户需要至少两部可播放、时长不低于 90 秒的视频；脚本会核对媒体库完整海报墙的项目数量和顺序。测试使用指定服务器的现有原始影片，不复制影片到仓库，也不下载视频文件。

~~~powershell
python Tools/Device-EmbyTest.py --serial <PICO_SERIAL> --server <EMBY_SERVER_URL> --username <TEST_USERNAME>
~~~

密码通过隐藏输入提示读取。自动化运行可将密码临时放入 `EMBY_TEST_PASSWORD` 环境变量，结束后移除变量；不要将密码写进命令行参数、脚本或提交文件。可用 `--adb <ADB_EXE>` 指定 Android SDK 的 adb。添加 `--capture` 会将首页、海报墙及影片详情的私人截图保存在忽略的 `Docs/Captures/`，不会自动复制到公开文档。

脚本检查独立服务端登录、媒体库及完整海报墙资料、影片简介和演员资料、原始视频尺寸、15 秒连续解码播放、暂停定位、Emby 进度同步 / 恢复、两部影片分别保存 VR 手动格式、最近记录，以及切回本地后的旧请求取消。连续播放要求焦点有效；设备提供佩戴状态时要求佩戴有效，无法提供时会单独记录这一边界。出现外部暂停、失焦、缓冲或停滞会使此次连续运行失败，恢复佩戴 / 焦点后应重新开始，不能拼接中断结果。

开始前会将设备的播放器设置、Emby 账户元数据、私有凭据 XML 及其 Android `.bak` 备份文件保存到忽略的 `Docs/Validation/*.backup.*`，记录原本不存在的文件。脚本结束时先停止应用和进度提交，再逐字节恢复四份设备文件并核对；原本不存在的文件会恢复为不存在。测试期间修改的服务端逐片进度、已看状态及已有播放统计也会恢复并核对；独立的验证登录会退出。清理或恢复失败会令测试失败，需查看忽略目录中的原始报告和备份后处理，不能当作通过。

运行时使用 `KEYCODE_WAKEUP` 和应用已有的不休眠行为，不修改 `screen_off_timeout` 或 USB 常亮设置。测试凭据只短暂写入忽略的本地命令文件和设备私有命令通道，传递后删除；传递失败也会执行清理。报告不输出服务器地址、账户、令牌、电影名或媒体路径。必须使用尚未登记到当前设备的独立测试账户，脚本会拒绝复用设备已有的同服务器 / 用户配置，避免测试注销影响原有登录；也应避免其他客户端同时更新相同影片的进度。

这项脚本验证的是开发命令驱动的真机浏览与播放，不能证明物理手柄按压 / 射线体验、文字可读性或双眼舒适度。15 秒连续播放也不等于长影片、全部编码、HDR 或全库 VR 格式兼容性验收。私人截图只能在检查隐私内容后人工选入公开文档；佩戴体验和长时间播放应单独记录。

### 分段正片与附加篇回归

~~~powershell
python Tools/Device-EmbyMoviePartsTest.py --serial <PICO_SERIAL> --server <EMBY_SERVER_URL> --username <TEST_USERNAME> --capture
~~~

这项回归核对电影库完整海报墙、人物简介及全部出演影片、类型 / 标签 / 制片厂分类和分类内搜索，以及电影库直接显示正片、详情的分段顺序与附加篇。播放检查覆盖普通电影不能跨片切换、分段上下边界、浏览其他 Emby 页面后的队列、手动选段与连播时的格式继承，以及附加篇组内显式切换、直接点选恢复自身设置和禁止自动连播。沿用上述四份设备文件与服务端 UserData 的严格恢复，并持续要求有效焦点、佩戴状态和新鲜诊断。

服务器没有 `AdditionalParts` 样本时，会明确跳过分段播放检查；不会用文件名模拟真实服务器识别结果。指定服务器已知存在真实分 CD 样本时，追加 **`--require-parts`**，未找到样本就会失败，不能以跳过作为通过。人物或分类元数据缺失时，相应检查也会明确记录跳过；模拟服务器则要求这些检查全部执行。

无真实分段样本时，可在独立终端启动只监听本机的模拟服务器，再通过 `adb reverse` 验证硬件通路。它使用本地已有测试 MP4，不复制真实影片。`--duration-ms` 必须与 MP4 实际时长一致，建议至少 30 秒。

~~~powershell
python Tools/Serve-EmbyMoviePartsFixture.py --media <LOCAL_TEST_MP4> --duration-ms 30000
adb -s <PICO_SERIAL> reverse tcp:18096 tcp:18096
python Tools/Device-EmbyMoviePartsTest.py --serial <PICO_SERIAL> --server http://127.0.0.1:18096 --username fixture --synthetic-fixture --require-parts --capture
adb -s <PICO_SERIAL> reverse --remove tcp:18096
~~~

模拟服务器密码为 `fixture`；只用于本机测试，令牌仅存内存。它提供 205 项影片目录、人物简介与出演影片、类型 / 标签 / 制片厂资料，以及 CD1 / CD2 / CD3、PV 与预告片，视频内容共用指定的本地测试 MP4。合成测试核对完整墙、人物和分类结果，还检查普通影片切入分段后替换队列，以及受控延迟接段期间浏览首页仍可连播。结束时停止模拟服务器，并只移除本轮新增的端口映射。报告单独记录合成范围，它不能证明真实 Emby 分段识别、真实局域网发现或长影片兼容性。
