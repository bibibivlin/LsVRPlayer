## 播放与性能

最终 APK 的整套设备回归 **24/24 通过**，包括本地 H.264/HEVC、暂停、三种中文 SRT 编码、字幕随 seek、SBS/OU 双眼与眼位交换、五种音轨、内嵌 SRT，以及 SMB 目录、H.264/HEVC 串流、中文 SRT 和前后跳转。高清档的 4K60 短片采样约 72 fps、解码丢帧为 0。完整记录为 `Validation/device-all.json`；ADB reverse 仅用于这组已有播放回归，独立的真实 LAN 发现测试见上节。

回归同时修正了重复打开兼容视频时的解码器名称显示：Media3 复用已有解码器时不会再次发初始化事件，因此名称现在只在实际释放时清空。运行日志中的 PICO SensorClient / CpuFreqPolicy 消息单独保留，未把 SDK 日志当作播放器异常或忽略所有错误。

短压力检查同样通过：4K60、8K30 截图时约 71.8 fps、解码丢帧 0；PSS 分别约 796 MiB 和 1,223 MiB。随后 6 次切换 H.264 / HEVC / 4K、seek 和播放耗时约 59 秒，预热后 PSS 905 MiB，结束 903 MiB，本轮没有观察到持续增长。记录为 `Validation/device-stability.json`。测试工具会先回到样片开头，避免旧的断点续播位置让短片在采样前结束。

所有高分辨率素材均为生成的低码率 SDR 短片。没有完成长片热稳定性、真实高码率 NAS 无线吞吐、扬声器听音/口型同步、佩戴后摩尔纹与闪烁主观对比。手柄双手舒适度和键盘输入全流程仍应由使用者在头显内体验；上述自动事件检查不替代人工体验。

`Validation/`、`Captures/` 是本机忽略的验证产物，不随源码提交；可以使用 `Tools/` 中的脚本重建。本报告与第三方许可保留在仓库中。

测试结束后已恢复设备原有设置、历史、收藏和 SMB 配置，并停止本轮临时测试服务器、移除 ADB 转发、恢复原 USB 唤醒设置。最终应用进程的 Unity / AndroidRuntime / VRPlayer 错误过滤日志无条目。
